# RFC: T1 stencil instantiation lands (machine code, W^X, deopt-to-T0)

## Summary

The codegen team is landing the T1 instantiation stage (the backend
milestone): the build-time stencil archive, the runtime instantiator, the
code cache, and the Tier-1 execution engine. After this lands, a
`StencilPlan` becomes **executable x86-64 machine code** and deoptimizes to
T0 exactly as `docs/deopt_backend.md` Part A specifies.

This RFC covers three things that cross team boundaries and therefore need
your sign-off before the code lands:

1. **The T1 activation record layout** (the machine-visible form of the
   T0-compatible frame, `docs/stencils.md` SS8) — pinned in the new
   `docs/codegen_contract.md`, cross-checked against `interp::Value` and
   `b2::rbc::RType` at compile time.
2. **Archive-only patch holes** — the archive's stencil descriptors carry
   additional declared holes (register-operand slot offsets, runtime-helper
   call sites, per-point deopt-thunk branches) beyond the holes the v0
   manifest declares. Stencil Rule 3 is upheld: every byte the instantiator
   touches is a declared hole *in the archive*; the manifest's holes remain
   the plan-value channel and keep their 1:1 alignment with plan
   `PatchValue`s.
3. **An availability flip in `builtinStencilSetV0()`** (baseline_noir's
   file, our request): `invokestatic` / `invokespecial` / `invokevirtual` /
   `invokeinterface` / `ldc`-of-String become `Available` because the T1
   runtime-helper seam now exists to execute them (see "Availability flip"
   below). The set version bumps; plans rebuild; golden dumps of methods
   that already planned are unchanged (availability only gates refusal).

## The T1 activation record (machine-visible frame)

`docs/stencils.md` SS8 pins "T1 frame model should be T0-compatible". The
concrete machine layout (all offsets in `docs/codegen_contract.md` SS3):

```text
rbp -> +0    magic                 (kT1ActivationMagic, defensive)
       +8    CompiledCode*         (owning instantiation: plan + real pc map)
       +16   exit status           (0 normal / 1 deopt)
       +24   deopt native offset   (offset within the code block)
       +32   deopt id
       +40   trap kind             (helper-raised traps)
       +48   pending exception     (ObjRef id; 0 = none)
       +56   reserved (align)
       +64   return Value          (16 bytes: tag @0, payload @8)
       +80   monitor count
       +88   monitor ObjRef ids    (kT1MaxMonitors = 16, u32 each)
       +152  slots: locals l0.. then regs r0.., one 16-byte Value each
```

- Locals first, then registers — one flat array, exactly the interp
  contract's `Frame` with `locals` and `regs` concatenated. Deopt is "build
  a `b2::interp::Frame` from the activation and call `Interpreter::resume`"
  (`docs/deopt_backend.md` Part A SS3; Amendment B.3).
- The GC team should note (SS8.2 in `docs/stencils.md`): a T1 frame's GC map
  IS the slot array — every slot is a tagged `Value`; scanning walks
  `[slotsBase, slotsBase + (numLocals+numRegs)*16)` and reads the tag.

## Archive-only holes (Stencil Rule 3 statement)

The v0 manifest declares the *relocation-relevant* holes (imm-based). The
archive (a build-time artifact generated by `tools/stencilgen`, Stencil
Rule 1: never generated at runtime) declares, additionally:

- register-operand holes (`InsA`/`InsB`/`InsDst` sources → frame slot byte
  offsets, baked from the RBC stream at instantiation — the documented
  "re-read from the stream by the instantiator" behavior),
- runtime-helper call sites (`CallRel32` + `RuntimeHelper`),
- per-point deopt-thunk branch targets (`BranchRel32`, instantiator-filled
  from the plan's `DeoptPoint`s).

Plans still fill exactly the manifest holes; `StencilInstance::patch_values`
keep their 1:1 descriptor alignment. The archive is versioned
(`kStencilSetVersionV1`), validated against the set at load AND at
instantiation (Stencil Rule 4), and deterministic (byte-identical across
runs — Rule 124; golden-tested by `tests/codegen`).

## Availability flip (baseline_noir sign-off requested)

`availabilityFor()` currently refuses the un-quickened `invoke*` and `ldc`
because "the v0 runtime cannot back them in compiled form". With this
landing, it can:

- `invokestatic`/`invokespecial`: MethodRef resolved at instantiation
  (`Runtime::resolveMethod`), executed by the T1 call helper.
- `invokevirtual`/`invokeinterface`: builtin probe then (name, descriptor)
  resolution in the call helper — the same resolution order T0 documents
  for the v0 no-hierarchy world (the IC seam stays the plug point for real
  vtable dispatch, exactly as `docs/icdg.md` Phase 1 leaves it).
- `ldc` of a String const: interned via `Runtime::internString`.
  (`ldc` of anything else stays `NeedsRuntimeFeature`.)

Effect on baseline tests: the three availability pins and the corpus sweep
expectations change (more methods plan); nothing else moves — the selection
algorithm, holes, dumps, and invariants are untouched. The set version
bumps to `kStencilSetVersionV1 = 2` so stale plans cannot instantiate
against the flipped manifest.

## Deopt contract (interpreter sign-off requested)

All T1 deopts (trap, call exception, guard failure) leave the compiled code
with the activation filled in (status, native offset, pending exception),
and the engine reconstructs a T0 `Frame` (locals, regs, monitors, pending
exception, pc) and calls `Interpreter::resume`. A deopted invocation
finishes on T0 — the documented baseline-tier behavior (Amendment A "always
safe to abandon"; the plan is a cache, not a correctness claim). Exception
unwinding across nested T1 activations dispatches per-frame: caught in the
caller's plan `exception_edges` → re-enter compiled code at the handler
native offset (frame reset: all regs Bottom, regs[0] = exception); not
caught → release monitors LIFO, propagate one level up.

## What we are NOT doing (v0 honesty)

- No IC patching in compiled code (call helpers resolve; the IC site id
  still travels in the plan's `CallSiteId` hole for the future).
- No OSR, no tier-up heuristics, no code eviction (code cache is an arena;
  Stencil Rule 9 counters are reported but never act in v0).
- No NaN boxing (Part XVIII stays off), no vector stencils (T2+).
- `invokedynamic`, `guard_class`, `deopt_trap` remain `NeedsRuntimeFeature`.

## Resolution (2026-08-30)

Landed. Sign-offs recorded in the commit: baseline_noir approved the
availability flip + set version bump (baseline tests updated in the same
change); interpreter approved the `Interpreter::resume` deopt
reconstruction usage (no interpreter files modified); ir/gc noted the
frame/GC-map statement (the T1 activation record is the GC's scanning
contract - all slots are tagged Values at `kSlotsBase`).

As-built deltas vs the proposal (all documented in
`docs/codegen_contract.md` v1):

- Helper calls use absolute addressing (`movabs r11, addr; call r11`), not
  rel32: the code block is mmap'd far from the binary text.
- Plan holes pair with plan PatchValues BY SOURCE (the archive's hole kind
  names the ENCODING, the manifest's the SEMANTIC value).
- The T1 activation gains `reenter` (reserved; v1's exception dispatch is
  engine-side - no longjmp anywhere).
- Exception dispatch is UNIFORM (athrow, helper traps, and callee-threw all
  take one path) and caught handlers RE-ENTER compiled code through the
  handler's entry stub.
- `multianewarray` refuses at the PLAN stage (manifest-level gap), not at
  instantiation; T0 executes it, so the fallback is transparent.
- W^X destruction flips the block back to RW before `free` (the allocator
  writes free-list metadata into the freed chunk).

Verification: 382 tests green across five suites (frontend 113, rbc 79,
interp 125, baseline 50, codegen 15); the codegen suite is the Rule-36
differential (interp corpus 14/14 + frontend corpus 8/8, byte-exact stdout
and exit statuses); ASan+UBSan clean under `-fno-sanitize-recover=all`;
archive + instantiation deterministic (byte-identical regeneration and
code dumps across runs); `fib(28)` executes ~1.3x faster than T0.
